Core idea: precompute cumulative values in O(n) to answer range queries in O(1). Three variants learned:
  - **Variant A (range sum):** 1-indexed arrays with sentinel at index 0, query on [l,r] uses `pref[r+1] - pref[l]`. For non-trivial functions, precompute powers of the base.

- **Sliding Window** — 7 DB sessions (LC 1358 was guided but never logged to DB). **1/5 consecutive severity ≤ 1** (lc567 severity 1, streak broken by guided session on LC 930). Understand five sub-variants:
  - **Longest valid** (expand when valid, shrink when invalid): LC 3 — longest substring without repeating characters. Hash map of last-seen indices for O(1) duplicate detection. Key trick: `left = max(left, seen[char]+1)` handles stale entries.
  - **Shortest valid** (shrink when valid, track min): LC 209 — minimum subarray sum ≥ target. Standard template: `for right / while sum >= target { update answer; shrink left }`.
  - **Fixed-size window** (fill, then slide one at a time): LC 438 — find all anagrams. Fill initial window, then slide: remove left element, add right element, check match. No inner while loop needed. Frequency array + `matches` counter for O(1) per-step checking. LC 567 — same template, return boolean instead of collecting indices.
  - **Longest with deletions** (maxFreq trick): LC 2831 — longest equal subarray after removing at most k. Window valid when `windowSize - maxFreq <= k`. The key O(n) insight: **maxFreq never decreases** — when shrinking the window, `freq[nums[left]]` decreases but `maxFreq` stays the same. This eliminates recomputation entirely.
  - **Iterate over unique count** (non-monotonic validity): LC 395 — when validity condition is non-monotonic (e.g., "all chars ≥ k"), iterate `currUnique` from 1 to `maxUnique`, run standard window for each. Track `countAtLeastK` (threshold crossing counter) instead of exact minimum frequency. O(26×n) = O(n).
  - **Counting exact matches with prefix zeros**: LC 930 — when `sum == goal`, each leading zero in the window is an additional valid starting point. Count = `1 + prefixZeros`. Shrink past leading zeros even when `sum ≤ goal`. Full `count += prefixZero + 1` when sum matches goal.
  Core insight: when a window is valid, all extensions are also valid (superset property). Two counting perspectives: count extensions right (`n-right`) or count extensions left (`left`). **LC 930 insight:** when array elements include zeros (which don't affect sum), each leading zero in a valid window is an extra starting point (count extensions left). This is a special case of "count extensions left" — `left` counts the extensions, but here `left` is incremented by sliding past zeros rather than being a global pointer.
